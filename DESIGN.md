## 1. Atmosphere & Identity
A Korean evaluation workbench: quiet neutral chrome, numbered preparation steps, readable numerical evidence, restrained teal actions. Its signature is a wide paired action trace above compact, explicitly scoped metric tables. No promotional content, invented results, uploads, training, configuration editing, or robot controls.

## 5. Components
- **Section**: semantic section, numbered/title heading, description, body. Neutral 1px border, 8px radius, 24px desktop/16px mobile padding.
- **Field**: visible label, native input/select/textarea, help. 44px minimum control height. Default, focus-visible, disabled, and validation states; label wraps rather than truncates.
- **Artifact picker**: preparation offers native OpenPI checkpoint and DatasetUI dataset selects above the manual absolute-path fields. Opening editable preparation loads read-only lists once; typing a new SSH host aborts and invalidates old lists but requires explicit refresh rather than launching requests per keystroke. OpenPI defaults to the remote user's cache checkpoint directory. DatasetUI reads the running registry and maps Docker bind paths to host paths, without editing DatasetUI or datasets. Preserve manual paths, show empty/error/warning states, and never auto-select an artifact or trigger episode metadata reads/evaluation.
- **Button**: inline icon + text; primary, neutral, danger. Minimum 44px hit area; hover wash, active opacity, focus ring, disabled opacity, loading text. No decorative animation.
- **Notice**: labeled status/error and recovery guidance. Error role alert; loading role status; no blank catch. Extensive discovery warnings live in a collapsed disclosure with a named, bounded scroll region.
- **Episode row**: native checkbox, episode index, length, tasks. Full-row target; selected wash plus check. Select-all and clear are explicit.
- **Run history**: native `select` labeled 실행 기록 in the header; each option shows config, status and creation time. Choosing one opens analysis. Persisted backend jobs only; loading, error and empty states are text.
- **History management**: a native modal dialog lists saved run sizes and terminal-run checkboxes. It owns a bounded list scroll, traps focus, restores the trigger on close, and requires an explicit destructive confirmation with selected count/size and resolved storage directory. Active/finalizing or unsafe files cannot be selected. Partial deletion failures remain visible and successful deletions disappear from history, analysis, and model comparison; late responses cannot resurrect locally deleted IDs. Only local canonical run JSON files are removed, never datasets/checkpoints. Use existing danger/wash tokens; the dialog fits mobile viewport insets.
- **Metric**: text label, numerical value, scope; unavailable values use an em dash, never zero.
- Error metrics show MAE (Mean Absolute Error), MSE (Mean Squared Error), and RMSE (Root Mean Square Error). The separate top-level Evaluation Results tab shows pooled all-episode full-chunk values and every EP's full-chunk values; the analysis workspace no longer repeats this summary. New results store per-episode chunk aggregates separately from legacy first-step metrics. Legacy reconstruction requires complete retained chunks; insufficient data stays unavailable. Completed saved runs can be selected for comparison, identifying model, checkpoint and run time; dataset/action/sampling/coverage differences are disclosed rather than ranking unlike evaluations. Tables own horizontal scrolling on narrow screens. Legacy MSE derives from unrounded stored RMSE, while new runs store MSE directly. MSE uses squared source units. Mobile channel panels use one column so full metric names remain readable.
- **Trace chart**: responsive SVG with measured width; prediction solid teal, GT dashed amber, labeled axes/ticks. Compact overview panels match a 192-unit viewBox to a 192px viewport, without CSS zoom or letterboxing. The data region spans y=40 to y=140 (100px); 14px tick text and the scientific-value gutter remain readable. They share one grid legend and keep the caption visually hidden. Under 240px width, stacked time ticks add 64 units and the inline viewport height matches the 256-unit viewBox without shrinking the data region. Detail and future-chunk charts retain their 340-unit viewBox and own legend/inspection. Accessible title/description, individual point inspection, CSV equivalent.
- **Metric table**: native table with caption and scoped headers; chunk metrics explicitly labeled. Bounded horizontal scroll, keyboard reachable.

## 6. Motion & Interaction
No looping or ornamental motion. Native controls respond immediately. Async actions disable their own submit control and show textual progress. Reduced-motion preference requires no alternate behavior because this unit has no animation. Active jobs lock all request-editing controls; history, chart selection, exports, theme, and cancellation remain usable. Host/repo/dataset changes invalidate dependent selections and abort stale requests. Episode reads are explicit, use the selected repo's Python environment, and include host/repo/dataset; typing a path does not launch SSH requests.

## 7. Depth & Surface
Borders and tonal layering; no shadows, gradients or glass. Radius 4px badges, 8px panels and controls. Selected state uses a wash, not an accent border. Only focus-visible gets a 2px accent outline.

## 9. Result Workspace
Top-level `WorkspaceNav` switches between preparation, analysis and evaluation results; a saved run opens analysis. The result toolbar holds the run summary, episode select and native exports. Analysis has Prediction, Metrics and Pre-release tabs. Prediction contains Joint / Cartesian coordinate buttons, whole / single stored chunk selection, and in-place channel expansion. Tabs use native buttons with `aria-pressed`, so selection is not color-only.

### Pre-release diagnostic receiver
Analysis exposes Pre-release with the same controlled episode/source frame. Opening it never starts inference. Explicit OFF-by-default attention capture uses a separate JAX process; a distinct CPU-only image/projection action loads recorded RGB and attaches the operational JIMTOF front calibration without model execution. Its head-fixed and distortion-unadjusted pinhole approximation is shown before capture and beside the resulting trajectories. It requires the exact high-speed-gripper URDF digest and verified dataset/action mapping. Unmatched datasets use an explicit unavailable state rather than inheriting a rig calibration. Existing attention and projection survive compatible recaptures. Late HTTP state snapshots cannot regress terminal SSE states.

The original RGB canvas hosts clipped inverse-preprocessing attention and bilateral saved-action TCP paths; image dimensions must decode correctly before overlays render. Projection-only frames default to original RGB, even without model preprocessing metadata. Layer, denoise and early/late/all controls use cached maps, defaulting to last step and an equal-weight average of all raw layers (before display contrast), with individual layers still selectable. A separate mass panel includes non-image attention, padding shares, sink tokens and descriptive action differences. Token view includes letterbox and can hide pure padding without changing numerical totals. Synthetic data is labelled and accepted only by opted-in test stores. Unknown calibration/pose is never invented. Desktop uses a 3:1 canvas/mass layout; mobile stacks with existing tokens. Contracts: `docs/diagnostic-execution.md` and `docs/camera-projection.md`.

Attention display defaults to selected-camera valid-region P95 with square-root contrast. Pure-padding patches do not set that range; partially valid patches retain their complete measured value. Zero-percentile sparse maps use the valid maximum. Unknown geometry explicitly falls back to shared linear scale. A raw shared-maximum linear option preserves cross-camera comparison; masses and exported data never change. The legend gives range, nonlinear mapping and saturated valid-patch count, warning that enhanced colors are not cross-camera comparable. An original/model-grid comparison mode shows both views of the same camera, step, layer and query; desktop pairs the canvases and mobile stacks them. Click/tap or a native patch-index field highlights the same patch in both views, with its original weight and padding classification. Pure-padding selections have no original-image location. Controls reuse Field/Button and the existing accent highlight token.

- **Grid**: Left arm occupies the left half, right arm the right half; each half has two panel columns. Joint has seven joints plus native gripper per arm; Cartesian has six pose axes plus native gripper. On mobile the arms stack and the document scrolls. Unconfigured/unrecognized source data stays a generic original-action view, never silently interpreted as pose or joint units.
- **Panels**: one legend for the grid; each compact header shows first-step MAE/RMSE over the complete scored first-step trace of the selected episode, never run-level chunk perDimension. That equals the full original episode only when every frame was scored; on legacy or quick-subset runs it covers the scored frames only. Axis unit reads `native / unknown`. Prediction solid accent, ground truth dashed target.
- **Cursor and window**: one controlled `(jobId, episode, sourceFrame)` cursor and inclusive `[startFrame, endFrame]` window owned by `ResultWorkspace`; no global store. Joint and FK share them through the Source frame / Window start / Window end fields and chart clicks. The initial window includes the last scored frame and the latest valid chunk endpoint of the selected episode; padded tails and fully invalid chunks never extend it. Source selection still starts at the first scored frame. Values snap to an existing source frame; time is `frame / FPS`. Episode or run change remounts the workspace and resets once.
- **Chunks**: separate episode/origin/horizon identity; x axis is `(origin + horizon) / FPS`. The Prediction selector chooses all chunks or one stored anchor and updates the shared time window to that chunk's valid end. Single-chunk plot and tooltip filter predictions but retain the global anchor color. Returning to all restores the full episode/chunk window. No separate Future chunks screen remains.
- **Overview inspection**: keep one compact GT-dashed / prediction-solid legend, with the existing blue-to-red anchor-order color scale. Pointer/touch inspection snaps to an integer source time and shares one vertical guide across panels without changing the selected inference anchor. A viewport-bounded, scrollable value card shows the active channel, source frame/time, exact stored GT and every valid stored prediction at that frame, with origin, zero-based horizon step, horizon length and color. Mark predictions omitted by display thinning; do not interpolate or substitute missing data. Escape or leaving the overview clears inspection; arrow-key frame selection also updates it.
- **Coverage line**: first-step scope (scored anchors / original frames, last frame, warm-up excluded) and future-chunk scope (H, geometric full/tail, fully valid chunks, valid rows) are separate spans. Legacy runs print `unknown` for every unrecorded field. A `Quick subset` tag appears when stride is not 1 or maxSamples is not 0.
- **Source and conversion**: declare Joint or Cartesian source, column mapping, units, absolute/delta/velocity semantics and nominal sign/zero agreement. Known exact joint names can initialize mapping, never units or semantics. Source Joint retains native joint values; Cartesian display uses mm and fixed XYZ RPY degrees (R=RzRyRx), including declared quaternion-xyzw sources. Grippers always retain native units. FK requires an absolute Joint declaration, units and profile. IK additionally requires shoulder-frame Cartesian poses, real URDF joint bounds and explicit observed/manual initial joints. Seeds are never invented. Solve predictions independently from GT, carry previous solutions inside trajectories, and reuse a chronological GT reference at overlaps. Successful IK must pass FK position/orientation residuals and bounds; failed points remain null. Label source / FK / IK provenance and state unavailable reasons rather than displaying the wrong coordinate space. Workers own numerical conversion and stale requests are terminated.
- Native RPY retains recorded winding and singular components, with only declared unit conversion. Quaternion sources are decomposed into display RPY; undefined singular components remain null.
- **Detail**: in-place channel expansion reuses the active Joint/Cartesian data, GT, colors, masks/wrap gaps and time tooltip. Draw every intersecting chunk when expanded, without the overview cap; single-chunk selection still applies. There is no standalone Detail tab. Channel selections are separate per coordinate mode, while time selection stays shared.
- **Focus**: opening expansion focuses its close button. Close/Escape returns to the active coordinate grid and focuses the selected channel. Closing the value card focuses its plot. Focus-visible retains the 2px accent outline.
- **Exports and metrics**: original result JSON/trace CSV and Metrics keep original-action semantics. Full coordinate JSON/CSV include all first-step/chunk rows, masks, nullable failures, units, source/FK/IK provenance and model/seed context; they are not reduced to the current window. Do not present IK joint differences as recovered original joint errors.
- **Modes**: light, dark and system share the token table above; the workspace adds no colors of its own.

Parent QA must also cover refresh/resume of active jobs, disconnect/reconnect snapshot, terminal stream closure, failed/cancelled jobs, history selection while another job runs, stale discovery responses, explicit episode validation, full trace/export correctness, and chunk sample horizon validity.
